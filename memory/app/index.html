KeyValueStore Memory Calculator How to use it

Your keys

Describe the keys you have or plan: how many, how long their names are, and what they hold. The calculator works out how much memory the server uses for them, the way each version of Redis and Valkey stores them.

As text

One line for each kind of key, the way the command line takes them. Edit it here or in the form.

Server settings

The settings that decide how values are stored. The defaults are each version's own. The names follow the server you pick: Redis 6.2 says ziplist where later versions say listpack, and only Redis 7.2 and later, and Valkey, have the set-max-listpack settings.

What they take

With every version

The same keys on each server. Pick a version to see it above.

Small strings packed into hashes

Many small strings cost more in key overhead than in data. Kept as fields of hashes instead, a few hundred to a hash, they fit in compact listpacks: user:1234567 becomes field 67 of hash user:12345.

How much RAM to plan for

The server needs more than its data. These figures are guesses you can change: what to expect depends on your workload.
